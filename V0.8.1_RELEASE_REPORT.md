# ProofOps V0.8.1 — Integrity-Hardened Release Report

## Release objective

V0.8.1 does not add another app or larger AI surface. It closes the semantic and composition failures discovered after V0.8's 200-test offline release, while preserving the previously qualified safety kernel.

The implemented workflow is intentionally described as **verified renewal outreach**, not full renewal resolution. ProofOps can prove what it read, what was approved, what external email effect occurred, and why a duplicate was not sent. It does not yet claim that a customer renewal is commercially resolved without a verified terminal business state/CRM-write path.

## Trust boundaries after V0.8.1

1. A run owns an immutable workflow/customer/renewal/GoalContract context.
2. One active business operation owns a renewal-outreach operation before planning begins.
3. Business evidence is run/customer/renewal scoped.
4. Gmail renewal intent is accepted only from an authoritative renewal thread; unscoped customer mail fails closed as ambiguous.
5. The planner proposes a typed semantic plan only; trusted code owns recipients, logical operation identity, risk and execution parameters.
6. Approval is bound to run + action + actor + semantic payload and uses the same injected safety clock as the workflow/effect ledger.
7. External confirmation, verified proof persistence and approval consumption commit atomically.
8. An uncertain provider outcome remains UNKNOWN/RECONCILING; it cannot blind-retry.
9. Completion uses only the GoalContract durably stored on the run.
10. Prior verified outreach is transport proof, not proof that the renewal itself is resolved.

## Demo behavior

The offline demo still proves the uncertainty case:

1. workflow prepares an exact approved outreach
2. provider commits the message but the response is lost
3. ProofOps records UNKNOWN, physical message count = 1
4. resume/reconciliation verifies the original message
5. run reaches `COMPLETED_VERIFIED`, physical message count = 1
6. repeat goal does **not** claim the renewal is resolved; it becomes `DEFERRED`, physical message count remains 1

## Claims that are now defensible offline

- the defined critical suite accepts no cross-run evidence attachment
- completion cannot substitute an easier caller-supplied GoalContract
- confirmed provider proof can be reconstructed after the tested persistence gap
- effect confirmation/proof/approval consumption is atomic in the repository transaction
- the tested uncertainty paths do not blind-retry
- concurrent same-operation claims converge to one owner in the tested repository model
- renewal evidence is not inferred from unrelated customer messages when a renewal identifier is supplied
- prior outreach does not falsely imply business renewal completion
