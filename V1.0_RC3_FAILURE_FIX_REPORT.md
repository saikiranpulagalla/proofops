# ProofOps V1.0.0-rc3 — Promotion Integrity Hardening

RC3 is a narrow promotion-integrity patch over RC2. It does not add Calendar, MCP, browser automation, another workflow, CRM write orchestration, or additional model authority.

## Gap closed

RC2 had five independent live qualification scripts, but their outputs were human-readable and were not cryptographically bound to one qualification attempt, one exact source tree and one deployment configuration. This created a release-process risk: individually successful results from different builds/deployments could be mixed accidentally.

## RC3 fix

A new `app.release.qualification` module provides:

- deterministic executable/qualification source-tree SHA-256 fingerprinting
- non-secret deployment fingerprinting
- gate-specific target fingerprints
- atomic JSON PASS receipts
- an ephemeral HMAC-SHA256 signature on each receipt
- strict five-gate bundle validation
- a machine-readable V1.0 promotion evidence manifest

A new `scripts/promote_v10.py`:

1. requires explicit `--execute-live`
2. creates one random qualification run id
3. creates one ephemeral receipt-signing key that is never written to disk
4. clears old receipts before starting
5. runs release preflight with `--require-live`
6. runs PostgreSQL, Sheets, Gmail, Gemini and E2E live gates
7. validates all five receipts against the same run/source/deployment
8. writes `V1.0_PROMOTION_EVIDENCE.json` only after complete success
9. removes/never writes promotion evidence on partial failure

The existing live smoke scripts remain usable standalone. Receipt emission is enabled only when promotion receipt environment variables are supplied.

## Adversarial RC3 tests

The 14-test promotion suite covers:

- receipt release identity binding
- raw target data not stored in receipt
- required shared qualification run id
- standalone smoke behavior without receipt collection
- complete bundle validation
- mixed qualification run rejection
- wrong release/Alembic head rejection
- missing gate rejection
- non-PASS receipt rejection
- database password redaction from safe identity
- promotion CLI explicit-live guard
- synthetic identity guard before providers run
- HMAC tamper rejection
- same-run valid receipts from different deployment configurations rejected
- source-tree mismatch rejection

Full historical regression remains green.
