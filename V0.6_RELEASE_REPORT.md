# ProofOps V0.6 Release Report — Google Sheets CRM Adapter

## Scope

V0.6 adds a production-shaped Google Sheets CRM adapter behind the existing `CRMPort`/`CRMWritePort` boundaries. It does **not** unlock Gemini to write Sheets directly, and it does **not** claim a live Google API/OAuth test in this offline build environment.

## Stable identity model

- Human-readable company names and row numbers are never used as write identity.
- Each renewal row is tagged with Google Sheets developer metadata:
  - key: `proofops_renewal_id`
  - value: the immutable business `renewal_id`
- At write time the adapter resolves that key/value to exactly one Google-assigned `metadataId`.
- The exact `metadataId` is then used for both mutation and read-back verification.
- Duplicate/missing metadata is a hard `ProviderConflict`.

## Write contract

`update_renewal_status(customer_id, renewal_id, expected_version, new_status)`:

1. Resolve exactly one provider metadata ID.
2. Read the row through that metadata ID.
3. Verify renewal/customer identity.
4. Require exact `expected_version`.
5. Permit only canonical renewal status values.
6. Increment version exactly once.
7. Write with Sheets `RAW` input semantics.
8. Require provider to report exactly one updated row when the field is present.
9. Read back using the same metadata ID.
10. Verify status, version, customer/renewal identity, and untouched critical fields.
11. Only then return `CRMUpdateResult(verified=True)`.

This is **optimistic conflict detection**, not a claim of provider-side atomic compare-and-swap against arbitrary external editors.

## Provider failure semantics

- 401/403 -> `ProviderUnauthorized`
- 429/5xx -> `ProviderUnavailable`
- malformed provider/business data -> `ProviderDataError`
- duplicate/missing/stale identity/version/postcondition mismatch -> `ProviderConflict`

Provider failures are never converted into `None` / "customer not found".

## OAuth/setup

- Runtime OAuth is explicit; no browser popup is triggered by the service during a demo.
- `scripts/bootstrap_google_oauth.py` provides one-time test-user bootstrap.
- `scripts/provision_sheets_crm.py` validates unique renewal IDs and attaches stable developer metadata.
- For the MVP's known test spreadsheet, the bootstrap uses the Sheets read/write scope. A future Picker flow can narrow this to `drive.file` without changing adapter semantics.

- V0.6 offline demo: PASS.

## Explicitly unqualified

- No live Google OAuth token was available in this execution environment.
- No live Sheets API mutation was performed from the Python adapter.
- No guarantee is made against arbitrary external editors racing a write between version check and provider commit.
- No multi-process adapter-local lock guarantee is claimed; ProofOps' durable effect/logical-action layer must serialize consequential runtime mutations.
- `UPDATE_CRM_STATUS` remains model-disabled until a live adapter smoke test and orchestration/effect binding are qualified.
