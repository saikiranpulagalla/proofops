# ProofOps V1.0.0-rc2 — RC1 Failure Fix Report

RC2 is a focused integrity/recovery patch over RC1. No Calendar, MCP, browser automation, new workflow, or additional model authority was added.

## Release blockers repaired

1. **False cancellation response** — reject now reports durable truth. Pre-claim cancellation can become `CANCELED`; after authorization is claimed/in flight it returns `TOO_LATE_TO_CANCEL`; completed runs return `ALREADY_TERMINAL`.
2. **Unreachable safe retry** — `RETRYABLE` is now a continuation of the same claimed authorization. It does not require a second approval claim and cannot change payload/run/customer/actor.
3. **Retry after business truth changes** — a retryable continuation is terminated if the deadline expires or CRM/Gmail material state drifts before retry; provider send is not called.
4. **Authoritative Gmail thread buried by sender search** — renewal-scoped evidence is fetched directly by configured Gmail thread IDs, not discovered from a truncated top-N sender query.
5. **Missing vs explicitly absent renewal conversation** — omitted renewal thread scope remains `AMBIGUOUS`; explicit `renewal_id: []` means the operator verified there is no prior authoritative thread and yields `NONE`.
6. **Synthetic naming was not a recipient boundary** — live mode requires an explicit normalized recipient allowlist; the authenticated Gmail sender and every configured CRM contact must be allowlisted, and the send wrapper enforces the same allowlist at dispatch.
7. **Immortal API idempotency request** — API request records now have leases. A stale request linked to a durable run recovers that run without replay; a stale request with proof that no run was committed can be safely reclaimed.
8. **Stale business-operation owner** — operation ownership is lease-backed. A stale owner with no action can be transferred after the old run is blocked; ownership with any consequential action cannot be stolen and must be recovered/reconciled.
9. **Stale worker after ownership transfer** — workflow ownership is revalidated before planning completes and again before the consequential effect boundary.
10. **Logout did not revoke a copied cookie** — sessions are now persisted server-side with expiry/revocation; logout revokes the session ID, so a saved pre-logout cookie is rejected.
11. **Public example credentials accepted** — known placeholder/default strings are rejected. Live runtime additionally requires HTTPS allowed origin and Secure cookies.
12. **Provider readiness was DB-only** — `/ready/providers` separately probes Sheets, Gmail identity, and Gemini while `/ready` remains a cheap DB/process readiness endpoint.
13. **Zero live reconciliation grace** — qualified live runtime requires at least a 10-second grace and at least two absence observations before `RETRYABLE`.
14. **Chunked request size bypass** — request-size enforcement moved to an ASGI receive wrapper so streaming/chunked bodies are counted before endpoint parsing.
15. **Low-level confirmed-action latent `now` bug** — confirmed effect evidence repair now consistently uses the injected safety clock.
16. **Live Gemini gate below target** — qualification is now 25 unique labelled scenarios, 20 critical, two trials by default (50 first attempts); critical semantic correctness must be 100%, overall >=95%, deterministic compiler containment 100%.
17. **Postgres gate did not prove concurrency** — live Postgres qualification now races separate transactions for business-operation claim, approval claim, effect claim, and API idempotency ownership.
18. **No final live composition test** — an explicit opt-in E2E harness now runs real Postgres + Sheets + Gmail + Gemini through the FastAPI session/CSRF/idempotency/approval flow, verifies one physical Gmail effect, cold-restarts, and repeats the renewal expecting `DEFERRED` with no second send.
19. **Gmail business evidence not live-qualified** — Gmail live smoke now also creates a unique synthetic evidence thread and proves real authoritative-thread reading/classification.
20. **RC metadata drift** — single-source release identity is now `1.0.0rc2`, Alembic head `0008`, and release manifests use exact revision/test counts.
