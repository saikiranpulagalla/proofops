## RC6 safety boundary

1. Explicit user no-contact intent deterministically forbids external outreach.
2. Obvious goal/company subject contradictions block before action creation.
3. The original "without contacting them unnecessarily" demo goal remains actionable.
4. Pre-effect freshness compares business meaning rather than trusting CRM version alone.
5. Same-version company/renewal-date drift invalidates approval with zero sends.
6. Approval TTL/window is part of authorization identity; different windows do not silently reuse authority.
7. Approval HTTP causality is bound to the exact durable `api_request_id`.
8. Deployment restart evidence uses a shared DB generation, not a process-local boot UUID alone.
9. Runtime images recompute/attest the executable runtime payload while carrying the frozen full-source identity.
10. Login throttling is shared in durable DB state across workers.

## Final live promotion still requires
