# ProofOps V1.0.0-rc1 Release Qualification Report

## Purpose

V1.0.0-rc1 converts the V0.9 offline-qualified prototype into a release candidate with an explicit real-provider composition root and reproducible live qualification harnesses. It adds no Calendar integration and gives the model no new authority.

## Live runtime composition

`PROOFOPS_RUNTIME=live` now wires the qualified components as one fail-closed runtime:

1. external PostgreSQL database at the exact qualified Alembic head
2. dedicated Google OAuth test-user token with Sheets read/write and Gmail modify scopes
3. Google Sheets CRM adapter
4. Gmail read/send/reconciliation adapter
5. authenticated Gmail sender-profile verification
6. CRM-to-Gmail contact identity verification
7. renewal-thread scope configuration
8. Gemini `gemini-3.8-flash` structured planner with zero tools
9. deterministic validator/compiler
10. existing approval/effect/evidence/completion kernel
11. existing authenticated/idempotent HTTP/UI boundary

There is no automatic fallback to fake providers if live configuration or optional dependencies are missing.

## Release-safety tooling

The repository contains four explicit live smoke tests:

- `scripts/smoke_v10_postgres_live.py`
  - exact migration revision
  - live transaction write/read/rollback
  - no provider side effect
- `scripts/smoke_v10_sheets_live.py`
  - requires `PROOFOPS_ALLOW_LIVE_SHEETS_SMOKE=YES`
  - accepts only `SMOKE-` customer/renewal identifiers
  - update/readback
  - stale-version rejection
  - status restoration
- `scripts/smoke_v10_gmail_live.py`
  - requires `PROOFOPS_ALLOW_LIVE_GMAIL_SMOKE=YES`
  - resolves the authenticated Gmail address itself
  - sends only to that same mailbox
  - persists verified provider evidence
- `scripts/smoke_v10_gemini_live.py`
  - requires `PROOFOPS_ALLOW_LIVE_GEMINI_SMOKE=YES`
  - synthetic contexts only
  - no model tools
  - ten first-attempt labelled planning trials
  - deterministic validator remains the execution boundary

`python scripts/qualify_v10.py` is non-network and reports live prerequisites as `PENDING` rather than treating their absence as success. `--require-live` turns pending prerequisites into a failing release preflight.

## Why this is RC1, not final V1.0

The current execution environment has no real Google OAuth token, Gemini API key/runtime package, or external PostgreSQL target. Therefore no source-code test can honestly replace the four live gates. V1.0.0-rc1 is the final offline-qualified candidate; final V1.0 requires those gates to run on the intended synthetic test accounts/deployment.

## Final V1.0 promotion rule

Promote RC1 to V1.0 only if:

- PostgreSQL smoke passes against the deployment database
- Sheets synthetic smoke passes and restores the test row
- Gmail self-send smoke passes with exactly one verified message
- Gemini live quality gate meets its defined threshold
- no live-discovered patch is needed, or any patch is followed by the complete regression suite
- the deployed `/ready` endpoint is green after a cold restart
- the 3-minute demo can be reset and rerun deterministically using synthetic data

Calendar remains out of scope unless final V1.0 is already green with schedule margin.
