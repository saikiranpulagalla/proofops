# ProofOps V0.8.1 — Integrity Hardening Fix Report

## Why V0.8 was reopened

V0.8's shipped regression suite remained green at 200/200, but a fresh adversarial audit found composition paths that were not represented in the original denominator. The defects were not treated as isolated bugs; the repair changed trust boundaries so the same failure class cannot re-enter through an alternate call path.

## Repairs

### 1. Cross-run evidence ownership

**Failure:** evidence could be recorded against Run B using an `effect_id` owned by Run A when `action_id` was omitted.

**Repair:** `record_evidence()` now resolves the effect's action and verifies that the derived action belongs to the requested run. Action-only, effect-only, and action+effect paths all enforce the same run identity.

**Kill test:** K01.

### 2. Persisted GoalContract is the only completion authority

**Failure:** completion could be evaluated against an easier caller-supplied contract instead of the immutable contract stored on the run.

**Repair:** `RunCoordinator.finalize()` no longer accepts a GoalContract argument. It loads and parses `run.goal_contract_json` itself.

**Kill test:** K02.

### 3. Confirmation, proof persistence, and approval consumption are atomic

**Failure:** a crash/DB failure after action/effect confirmation but before provider evidence persistence could leave a confirmed effect with no completion proof and no recovery path.

**Repair:** `confirm_effect_with_evidence()` commits effect confirmation, action confirmation, exact evidence insertion, and approval consumption in one DB transaction. A confirmed effect missing proof can also reconstruct proof through provider re-verification on resume.

**Kill tests:** K03, K04.

### 4. Repeat outreach is not business completion

**Failure:** a later run could treat prior verified outreach as `COMPLETED_NO_ACTION_REQUIRED` even when the customer had since accepted, declined, or requested no contact.

**Repair:** prior outreach is durable transport proof only. Current business evidence is evaluated first. When the renewal is still unresolved, a prior confirmed outreach causes `DEFERRED`, not business completion; accepted/declined/DNC evidence routes to human/business resolution until CRM-write orchestration exists.

**Kill tests:** K05–K07, K19.

### 5. Renewal-scoped Gmail evidence

**Failure:** the newest email from the customer could steer a renewal even when the message belonged to an unrelated conversation.

**Repair:** the Gmail business-read port now accepts `renewal_id`. The Google adapter requires an authoritative renewal-to-thread mapping for consequential renewal interpretation; without one, customer mail is `AMBIGUOUS`, not equivalent to no evidence. Messages outside the renewal thread are ignored for renewal intent.

**Kill tests:** K08, K18.

### 6. HTML quoted-history protection

**Failure:** HTML `<blockquote>`/Gmail quoted history could be flattened and misclassified as fresh customer intent.

**Repair:** HTML business evidence extraction removes common Gmail/Outlook/Yahoo/Mozilla quote containers before intent classification while leaving outbound transport verification unchanged.

**Kill test:** K09.

### 7. Terminal status precedence

**Failure:** an already-renewed record with a past renewal date could be blocked as overdue.

**Repair:** normalized terminal CRM states are evaluated before nonterminal overdue-window rules.

**Kill test:** K10.

### 8. Explicit planner retry path

**Failure:** a planner exception could strand a durable run in `PLANNING` with no workflow-level recovery method.

**Repair:** `retry_planning()` reconstructs planning inputs from durable context; `resume()` routes a PLANNING run with no action through that path. Planner failure is visible as a checkpoint reason rather than disappearing as an exception-only state.

**Kill test:** K11.

### 9. Business-operation ownership before planning

**Failure:** simultaneous prepares for the same renewal could both pass the early duplicate check and collide late at action creation.

**Repair:** a unique durable `business_operations.operation_key` is claimed before planning. Exactly one active run owns the operation; followers fail closed with the owning run reference. Ownership can transfer only after the prior owner is non-active/terminal.

**Kill test:** K12. Repeated 5/5 additional times after the full suite.

### 10. One injected safety clock

**Failure:** workflow deadline, approval TTL, effect evidence, and execution leases could use different clocks.

**Repair:** the workflow composition root injects the same clock into repository, approval service, and effect executor. Safety-critical approval timestamps and leases no longer call an independent wall clock.

**Kill tests:** K13, K14.

### 11. Immutable evidence-source drift detection

**Failure:** the same `(run, evidence_type, source_ref)` could be recorded later with changed content and silently return the old record.

**Repair:** exact same evidence is idempotent; identity change or immutable content change raises an explicit drift error. Re-observation time may advance without changing the evidence value.

**Kill test:** K15.

### 12. Validate goal input before durable run creation

**Failure:** a timezone-naive deadline could fail after a run had already been created, leaving a stranded RESOLVING run.

**Repair:** goal text/company/deadline validation happens before `create_run()`; deadlines must be timezone-aware.

**Kill test:** K16.

### 13. Run-scoped recovery

**Failure:** resuming one workflow could call a global expired-execution recovery and mutate unrelated runs.

**Repair:** workflow resume uses `recover_expired_execution(action_id)` for only its own action. Global recovery remains available for a dedicated recovery worker, not an interactive run resume.

**Kill test:** K17.

### 14. Honest workflow scope

**Failure:** the product wording could imply that a verified outbound email meant the entire renewal was resolved.

**Repair:** V0.8.1 explicitly scopes the implemented workflow to **verified renewal outreach**. A confirmed prior outreach prevents duplicates but does not prove a renewal case is resolved. CRM mutation remains outside the composed planner execution path.

**Kill test:** K19 plus revised repeat-goal regression.

### 15. Release/API metadata

`/health` and package metadata now report V0.8.1 integrity hardening rather than the older safety-kernel version.

**Kill test:** K20.

## Regression result

- New V0.8.1 integrity kill suite: 20/20 PASS
- Combined suite: 220/220 PASS
