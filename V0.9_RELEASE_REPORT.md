# ProofOps V0.9.0 Release Report

## Purpose

V0.9 hardens the external HTTP/browser/deployment boundary around the already-qualified V0.8.1 workflow. It does not add Calendar, broader autonomy, or new model authority.

## New guarantees under the defined API test suite

- the browser cannot select the authorization actor; it comes from the signed server session
- run ownership is durable and foreign run IDs are not readable/actionable through the API
- mutations require a valid SameSite session, matching CSRF token and (when configured) same trusted Origin
- all workflow mutations require an `Idempotency-Key`
- a key reused with a different request body is rejected
- an exact completed request replay returns the original response rather than re-running the workflow
- an API request whose outcome is still in progress/unknown fails closed rather than being automatically repeated
- duplicate execute requests produce one physical message in the qualified model
- a new execute request against UNKNOWN/RECONCILING/EXECUTING work routes to resume/reconciliation rather than a fresh send
- approval rejection cancels the run/action before any external effect
- run/evidence/audit detail is actor scoped and approval nonces are never exposed
- no known default credential is enabled by an unconfigured deployment
- configured HTTPS origins require Secure cookies; security headers include CSP/frame denial/HSTS where appropriate
- oversized request bodies are rejected before workflow execution

## Persistence change — 0007

- `runs.owner_actor` binds an API-created run to the server session actor
- `api_requests` persists actor/route/idempotency-key/request-hash/state/response for restart-safe replay semantics
- legacy V0.8.1 runs migrate with `owner_actor = NULL` and therefore are not implicitly exposed through the V0.9 API

## Explicit limitations

- single-user demo authentication, not enterprise/multi-tenant identity
- no distributed login-rate limiter
- live Sheets OAuth/API gate remains pending
- live Gmail self-send/reconciliation gate remains pending
- live Gemini quality/adversarial gate remains pending
- external Postgres deployment has not been exercised from this offline environment
- an API crash before an idempotency response is persisted is surfaced as `REQUEST_OUTCOME_UNKNOWN`; it is never auto-reexecuted

## Next legitimate gate
