# ProofOps V0.7.0 Release Report

## Objective

Introduce a real Gmail adapter without weakening the V0.4.5 safety kernel. V0.7 qualifies Gmail MIME construction, provider error semantics, deterministic reconciliation identity, raw read-back verification, and conservative inbound business evidence parsing.

## Architecture change

V0.6 still had the effect engine importing timeout/search exception classes from `fake_gmail`. V0.7 removes that coupling. Both fake and Google adapters now implement the same provider-neutral Gmail contract:

- `GmailOutcomeUnknown`: send may or may not have committed; reconcile first
- `GmailSearchUnavailable`: provider truth cannot currently be read
- `GmailSendRejected`: provider definitively rejected the send
- `GmailMessage`: typed observed provider effect

This prevents test doubles from defining production semantics.

## Outbound send path

1. ConsequentialActionService policy-checks and persists exact canonical payload.
2. Human approval is bound to run/action/actor/payload.
3. Effect ledger assigns deterministic logical effect identity.
4. Gmail adapter creates raw MIME with deterministic RFC822 Message-ID before dispatch.
5. Gmail send response is not treated as proof.
6. Provider is searched by `rfc822msgid:<id>` with `SENT` filtering.
7. Raw observed message is decoded and recipient/subject/body/hash are compared to persisted intent.
8. Only exact proof can move effect to CONFIRMED and persist evidence.
9. Any ambiguous send outcome moves to UNKNOWN and the existing reconciliation window applies.

## Inbound read path

For the synthetic demo, customer IDs are bound to verified customer email addresses outside the model. Gmail search returns candidate messages, but the raw From header is checked again. Auto-replies and quoted-only content are flagged. A small deterministic classifier recognizes only explicit accepted/declined/delay/do-not-contact phrases; any other human content is AMBIGUOUS rather than silently treated as absence.

This is intentionally narrower than general semantic understanding and is safer for the hackathon gate.

## New tests

The V0.7 suite adds coverage for:

- exact MIME body round-trip including terminal newline
- unicode subject
- normalized recipient
- non-SENT match exclusion
- missing send response ID
- invalid deterministic Message-ID
- malformed raw/base64 data
- no-message vs provider-unavailable distinction
- accepted/declined/delay/do-not-contact/ambiguous inbound evidence
- contradictory intent phrases
- quoted-only evidence
- automatic replies
- wrong From sender
- newest-message selection
- malformed provider timestamp
- full adapter + effect-ledger confirmation
- timeout-after-commit reconciliation without duplicate
- definitive rejection -> FAILED
- 401/403/429/400/5xx Google transport mapping

Full offline suite: **178/178 PASS**.

## OAuth decision

The test-user bootstrap now requests Sheets read/write plus `gmail.modify`. Gmail verification and reconciliation require mailbox read/search access in addition to send, so `gmail.send` alone is insufficient for this architecture.

The hackathon build must use a dedicated synthetic test account. Public OAuth production verification is explicitly outside this release claim.

## Live qualification

The repo contains `scripts/smoke_v07_gmail_live.py`. It refuses to run without an explicit environment flag and sends only to the authenticated mailbox itself. It exercises the hardened approval/effect/evidence path and requires `CONFIRMED` plus exactly one durable verified evidence record.

This environment did not have authorized Google test credentials, so the live gate remains **PENDING** rather than being simulated as success.

## Claims we do not make

- exactly-once Gmail delivery
- zero provider eventual-consistency risk
- production/public OAuth approval
- generic natural-language email understanding
- real-customer safety validation
- model-controlled Gmail execution

## Next stage

After live Sheets + Gmail smoke tests are green, V0.8 should be an end-to-end adversarial integration gate (real Sheets reads, real Gmail reads/send/reconcile, durable GoalContract completion), not Calendar feature expansion yet.
